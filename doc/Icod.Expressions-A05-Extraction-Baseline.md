## Behavior and gap ledger

The [A01 audit](Icod.Expressions-A01-POSIX-Semantic-Audit.md), draft
[BRE](POSIX-BRE-CONTRACT.md) and [ERE](POSIX-ERE-CONTRACT.md) contracts,
[A02 bit/profile matrix](Icod.Expressions-A02-GNU-Syntax-Bit-Matrix.md),
[A03 consumer matrix](Icod.Expressions-A03-Consumer-Compatibility-Matrix.md),
and [A04 index](Icod.Expressions-A04-Characterization-Index.md) describe the
semantic scope of these fixtures. The copied engine must preserve inherited
outcomes, including the following known limitations:

| Observation | Extraction disposition |
|---|---|
| GNU Extended empty-anchor alternation yields a participating empty capture in both branch orders where pinned Gnulib `test-regex.c` expects an absent capture in analogous cases. | Unresolved differential. Preserve the characterized result during E01/E02; adjudicate after exact parity. |
| Mid-branch anchors remain literal in Basic and Extended; a pattern newline remains literal rather than Gnulib `RE_NEWLINE_ALT`. | Missing syntax-bit/profile behavior, characterized locally. Do not claim exact Gnulib profile conformance. |
| Multi-scalar collating elements receive a controlled unsupported diagnostic; strict POSIX BRE/ERE do not have separate selectable providers. | Known scope and conformance gaps. Do not label the inherited providers strict POSIX. |
| The `tac` consumer supplies Emacs options to a Basic provider, which overrides syntax. | Known consumer bug, [Icod.CoreUtils #190](https://github.com/uniblab/Icod.CoreUtils/issues/190). Preserve the call shape during extraction; fix in the consumer later. |
| An exploratory GNU grep 3.11 comparison differs for a middle-anchor ERE pattern. | Profile discrepancy, not a pinned Gnulib oracle result; see [A04 probe](Icod.Expressions-A04-GNU-Grep-Probe.md). |
| The pinned Gnulib engine and an executable strict POSIX oracle are not integrated into the test suite; locale and full consumer-level behavior remain incompletely differential-tested. | Explicit characterization gaps, not proof of agreement or a reason to rewrite extraction expectations. Close for later standards/profile normalization. |

The A00 provenance ledger records Git introduction commits and attribution
for all source/test paths. It does not establish that every historical
fixture was original. Preserve the existing LGPL-3.0-or-later package
expression, license text, test history, and source attribution during the copy;
do not relicense or describe unverified fixtures as original.

## Reproduction and handoff

With .NET SDK 10.0.402, the in-place Staging run on the A04 test update
passed 193/193 focused cases and 531/531 total CommandFramework tests, with
no skipped tests. The 44-case JSONL verifier passed byte-for-byte, and the
compiled API export still matches its frozen file byte-for-byte. The
[three-platform CI run 39867051683](https://github.com/uniblab/Icod.CommandFramework/actions/runs/39867051683)
passed at A04 commit `797f9d3e36c3b5ee0f7faa9a45ddb567ab3d787c`, including
the suite, parity verifier, and regex benchmark smoke steps. The only new
content in this A05 commit is this evidence record; source, tests, runner,
and fixtures are not changed by the freeze.

```sh
git ls-tree -r e1e118f18246eed290bee4758325a20e302bfb92 -- src/RegularExpressions src/Text/TextDecodingMode.cs src/Text/InvalidEncodingPolicy.cs
git ls-tree -r 797f9d3e36c3b5ee0f7faa9a45ddb567ab3d787c -- tests/CommandFramework.Tests/src/RegularExpressions doc/Icod.Expressions-A04-Parity-Baseline.jsonl
dotnet run --project tools/RegularExpressionParityBaseline/RegularExpressionParityBaseline.csproj -c Staging -- --verify doc/Icod.Expressions-A04-Parity-Baseline.jsonl
```

At E00, transplant the exact focused tests, fixture and runner before the
production source. At E01, copy rather than remove the audited source and
its two external enums, making only project/namespace/accessibility changes
needed by the package boundary. At E02, compare the copied runtime with the
frozen JSONL and focused tests; reconcile the public API against the snapshot
with an explicit identity mapping for namespace/assembly changes. An exact
copy is not permission to remove or redirect the old implementation. Such
changes require a separate consumer-validated PR after a solid new library
exists.
